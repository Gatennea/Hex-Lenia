## 一、逐项解决方案与难度评估

难度标尺：**低** = ≤半天、机械性、有安全网｜**中** = 0.5-2 天、需设计、影响面可控｜**高** = >2 天或触及核心状态。

### 问题 1：单文件巨型化 —— 拆分为零构建多文件

**方案**：
- `index.html` 降级为**薄壳**（仅 DOM 结构 + 加载顺序，目标 ~200 行）
- JS 拆 4 件：`js/constants.js`（魔法数字，见问题7）→ `js/core.js`（FFT/核/步进/预设/序列化）→ `js/render.js`（纹理/调色板/绘图）→ `js/ui.js`（控件/事件/toast/诊断/存档/画廊，顶层最后调用 `init()`）
- CSS 全部迁 `css/style.css`（`<link>` 引入）
- **红线约束**：不用 ES modules——Chrome 对 `file://` 的 module 脚本会 CORS 拒绝，"双击可玩"会坏。用经典 `<script>` 顺序加载 + 共享全局（与现 lifecreatures.js 同机制），**零构建工具**
- 数据文件迁 `data/`（`<script src="data/lifecreatures.js">`）
- 每次改动的安全网：`node tools/test_node.js` + `?selftest=1` 浏览器自检 + 截图目视

**难度：中**。机械性强但触及全部 1683 行；风险点是加载顺序与初始化时机（现顶层副作用代码要挪进 `init()`）。回归网完备，可一次 commit 完成。

**收益**：编辑定位成本 ↓、diff 可读性 ↑、为问题 4 铺路。

### 问题 2：死代码/占位代码 —— 删 + 用 lint 固防

**方案**：
- 删除 `index.html:705` 的 `tmpRe` 占位对象（自承 unused，getter 永远 undefined）
- 引入 ESLint `no-unused-vars` 全量扫一遍（配合问题 3），人工复核后删：未用函数/变量/参数、`loadPattern` 之外的脚本残留
- 数据文件不再视为"残留"：归入 `data/`（见新结构），`.gitignore` 已负责日志类

**难度：低**。半天内含 lint 清零。**必须在问题 3 的 lint 就位后做**，否则删了还会再长。

### 问题 3：工程化基础设施 —— package.json + ESLint + GitHub Actions

**方案**：
- `package.json`（零运行时依赖）：
  ```json
  { "scripts": {
      "test": "node tools/test_node.js && node tools/test_unit.js",
      "check": "node --check js/core.js && …",        // 语法门
      "serve": "python3 -m http.server 8081" } }       // 沿用现约定
  ```
- ESLint（flat config，仅 `no-unused-vars`+`no-undef` 级别的防回归规则；**不上 Prettier**——全库重排格式会污染 git blame 与 diff）
- `.github/workflows/ci.yml`（约 20 行）：push/PR 时跑 `check` + `test`
- 手动约定文档化：`tools/README.md`（见问题 6）

**难度：低**。合计约半天。**放在最前面**：此后所有重构都有自动回归门。

### 问题 4：全局状态耦合 —— 两层解耦（先 API 边界，后实例化）

**方案（Tier 1，本次执行）**：
- **依赖方向单向化**：`ui → render → core`；`core.js` **零 DOM 访问**（不碰 document/canvas，仅挂载导出），render/ui 只经 `window.HLEN.core` 公开 API 取状态，禁止伸手进 core 内部
- 新增 `tools/test_unit.js`：在 Node 里**单独加载 core.js**（无 DOM 桩）做纯函数单测——
  GROWTHS 数值与峰值位置、CORES 形状、buildKernel 归一化(ΣK=1)与对称性、FFT 往返误差、`lifeRuleParse`/`serializeState` 往返
- 这直接兑现问题 4 承诺的"单元测试"，且 test_node.js 降级为纯冒烟

**方案（Tier 2，标记为可选/暂缓）**：
- `createSim(config)` 工厂把 30+ 全局收进实例，UI 持有单例——彻底解耦但**触碰 step()/渲染/预设全部路径**，改动量 ≈ 一次全库重写
- 建议：Tier 1 落地、单测覆盖核心纯函数后，若仍感不足再开 Tier 2

**难度：Tier 1 = 中（1 天，随拆分顺路完成）；Tier 2 = 高（另立专项）。**

## 二、执行顺序（我的决定）

原则：**先安全网、后动骨架、再清外观、功能殿后**；长跑复核（5a）不依赖结构，随时后台并行。

```
P1 安全网与快赢（≈1 天）
   ① #3 package.json + ESLint + CI         ← 从此每个 commit 有自动门
   ② #2 删 tmpRe + lint 清死代码           ← 依赖 ①
   ③ #6 tools/README + npm 别名
   ④ #5a 57种×2000步长跑（nohup 后台并行，不占人力）
P2 结构解耦（≈1-2 天，核心工程）
   ⑤ #1 拆分 index.html → css/ + js/{constants,core,render,ui} + data/
   ⑥ #4 core 零 DOM + HLEN API + test_unit.js   ← 与⑤同一批完成最省力
   验收：check + test + selftest + 截图 四关全过
P3 清理与归档（≈0.5 天）
   ⑦ #7 命名规范化 pass（常量已在⑤迁移）
   ⑧ 文档归位 docs/ + 交叉引用修补 + 问题文档勾稽
P4 功能与研究（按价值/成本比，独立可插拔）
   ⑨ #5c URL 分享(低) → ⑩ #5d per-rule R(中低) → ⑪ #5e 时间回溯(中低)
   → ⑫ #5f 多环核(中) → ⑬ #5g WebM 录像(中低) → ⑭ #5b 方格端原版校准(中高,研究性收尾)
```

**排序理由**：
1. 没有 CI/lint 就拆 1683 行 = 裸奔；安全网必须最先
2. 拆分（⑤）是解耦（⑥）的物理前提，两者同批做只付一次"全量回归"成本
3. 命名改动横跨全文件，放在结构稳定后一次做完，避免两轮全量 diff 叠加
4. P4 全是独立功能，不阻塞也不被阻塞——按"改动小价值大"排序，研究性最强的校准放最后

**总工作量粗估**：P1+P3 ≈ 1.5 天，P2 ≈ 1-2 天，P4 每项 0.5-1 天。


**加载契约（index.html）**：
```html
<link rel="stylesheet" href="css/style.css">
<script src="data/lifecreatures.js"></script>   <!-- 数据 -->
<script src="js/constants.js"></script>
<script src="js/core.js"></script>               <!-- 纯引擎，无 DOM -->
<script src="js/render.js"></script>
<script src="js/ui.js"></script>                 <!-- init() 在此触发 -->
```

**解耦边界三条铁律**：
1. `core.js` 不得访问 `document`/DOM——违反即单测能力归零
2. `render/ui` 只经 `HLEN.core` 公开 API 读写状态，不直接伸手（Tier 1 落地后由 ESLint `no-undef` 辅助约束）
3. 依赖只允许单向：`ui → render → core`；`constants` 被三者读取但不依赖任何一方

**为什么不用 bundler/TS/ESM**：项目红线是"零依赖、双击可玩、python 起服务即用"。
经典 script 标签在这三条下全部成立；ESM 会在 `file://` 被 Chrome 拒绝。解耦靠**文件边界 + API 契约 + 单测**实现，不靠编译器。
