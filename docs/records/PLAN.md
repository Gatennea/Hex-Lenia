## 已修复的关键缺陷（本轮）

1. taps 未与空间核同步归一化 → FFT 与直接卷积不一致（maxErr 22 → 7.8e-16）
2. 捕食者初始密度过高 → 压制恒 −1 → 猎物必死 → `initMul` 稀疏播种
3. 窄 σ 压制 → 猎物斑纹侵蚀崩塌 → 宽弱压制 (σ=0.15, h=0.35)
4. 渲染分桶：多物种 `bucketKey` 从不清零（残留旧键 → 错色）+
   预设切换未按 512 重分桶数组（按 64 越界丢格）
5. 平滑渲染右上黑三角：fitView 边界框比内容宽，主份未环绕溢出只在高行填满留白区
   → 裁剪到内容框 [-0.5, W+0.25]×[0, H·√3/2]（右缘取主份最小覆盖，零缝隙）；
   像素行扫描验证：六行全部 [180,1229] 均匀
6. 渲染派发插入时残留重复 `function render(){` → 语法错误（已删）

## 原版预设移植实验（experiment_orbium.js，结果 data/exp_result.txt）

**问题**：原版 Lenia 的预设在六角版行为会很不一样吗？

**方法**：从 Lenia-LifeForms.js 提取 Orbium 原始规则+种子（忠实移植原版 ToCellArray
zip 解码器，20×20 生物解码成功），并写方格对照引擎（同一套核/增长/更新代码，
只换晶格），六组对照各 300-600 代。

**结论**：
1. 规则代码忠实性 ✓ — 方格对照组中 Orbium 存活、形态保持、以 ~0.24 格/代滑行
2. **原版 Orbium 种子移植六角 → 100 代内灭绝**（方格同代码同参数存活）——
   纯晶格效应：6 重 vs 4 重对称 + 核采样点不同，生物的精细平衡被打破
3. **原版参数族在六角随机初始化全部存活**（密度 ~0.21），但活性排序：
   我们默认(R=10,σ=0.016) 1.0e-3 > Orbium参数(R=13,σ=0.017) 7.6e-4 >
   消融组 4.7~5.4e-4 —— 原版参数在六角偏“静”
4. 启示：参数可直接迁移并微调；**生物种子不可迁移**，六角需要自己的物种
   （60° 滑行方向、6 重对称形态），可在本版上重新探索

## 生物发现器（本轮：三条路线 + 渐变行走）
工具：find_creatures.js（batch/islands/walk 三模式）+ 软化预处理 + 形态/振荡/飞行分类

**路线结果记录**：
- ① 孤岛打捞（蠕虫场分离组织）：2 轮边距（2/4）× 全值提取 → 全部 DEAD
  结论：蠕虫场是"群落"（tissue），依赖周围场的卷积上下文，非独立个体
- ② 种子矩阵：水母突变（flipH 死/flipV 活/截肢死 → 生物有手性）、6 种新手绘种子
 （chevron/L/arc/tri/blob/ringHalf）、软化处理、放大锥体、水母缩放 0.8×/1.3×、
  噪声斑 r8-20 → 全部 DEAD 或 FIELD。规律：
  (a) 硬边种子同步崩落必死（需软梯度）(b) r≤R 的斑全是“边界细胞”被外部零值拖死
  (c) 长到临界质量就直接爆成场（σ0.016-0.025 无“稳定球”区间）
- ③ 渐变突变行走 walk（论文2.3.2自动化）：v1 小扰动208轮全存活但形态差恒0.006
  → **水母是自我修复孤子**；v2 加大扰动/结构破坏81%回滚；v3 加“结算期”
  （大突变后静置150步再测）→ 所有存活结算形态 diff≤0.08 全部回归水母
  参数走廊实测扩展：m∈[0.136,0.153] σ∈[0.012,0.020] 均可存活

**核心结论**：经典参数点 (R10, m0.15, σ0.016) 的水母是超强吸引子，种子空间邻域无新物种；
新物种可能在 (a) 其他 R（原版生物库 R 分布 13/18/36/27 为主）(b) 更宽 σ (c) 更大随机海选中

**下一步候选**：
1. LifeForms 规则移植扫描：原版 330 份规则（含宽 σ 如 0.0358）× 原版种子 → 六角存活率
2. 大规模随机海选：随机噪声场 + 孤立化处理 × 参数网格，批量后台跑
3. walk 加 R 维度（需从场/噪声出发，水母在 R 变化时无法架桥）
